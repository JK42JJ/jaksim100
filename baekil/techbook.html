기술서적 — 코어 쿠버네티스

← 콘솔로
제이 바이어스·크리스 러브, 김영기 옮김(위키북스). 08-27 시작, 4장 cgroups까지 읽었다. 남은 11장을 주 1장이면 11월 말에 끝난다.

읽는 법 — 하루 30분

  • 읽기 15분, 손 15분. 한 절을 읽고 바로 그 절의 명령을 친다. 다 읽고 나서 실습하지 않는다. 4장을 "힘겹게 읽고 개념만 잡은" 이유는 손이 없었기 때문이다.
  • 장마다 질문 하나를 먼저 적는다. "이 장이 끝나면 내가 뭘 설명할 수 있어야 하나." 예: 4장이면 "파드의 CPU 제한이 cgroup 어디에 어떻게 적히나."
  • 실습 환경은 kind 하나. 맥북에서 kind create cluster --name core. 노드 안은 docker exec -it core-control-plane bash로 들어간다. 책의 /sys/fs/cgroup, containerd, kubelet 실습이 다 여기서 된다.
  • 끝나면 한 줄. 콘솔 오늘 탭 기술서적에 "4장 cgroups, kind 노드에서 cpu.max 확인"처럼 장·주제·실습을 적는다. 이 줄이 독서 페이지에 코멘트로 쌓인다.
  • 면접에 바로 쓴다. 장마다 면접 답 한 문장을 만든다. 4장이면 "파드 CPU 제한은 cgroup v2 cpu.max 로 걸리고 스로틀은 cpu.stat 에서 봅니다." 이런 문장이 무신사·카카오 기술 면접의 재료다.

장별 계획과 실습

다음에 읽을 책 (순서대로)

  • 쿠버네티스 인 액션 2판(마르코 룩샤) — 코어 쿠버네티스가 '왜'라면 이 책은 '어떻게'다. 한 권으로 실무 전체를 덮는다.
  • Kubernetes Patterns 2판(빌긴 이브리암·롤란트 후스) — 파드·컨트롤러·설정 패턴 30여 개. 설계 면접에서 이름 붙여 말할 수 있게 된다.
  • Production Kubernetes(조시 로소 외, O'Reilly) — 멀티테넌시·네트워크·관측·보안을 운영자 시각으로. 카카오페이증권 같은 SRE 면접의 질문 은행이다.
  • Site Reliability Engineering과 The Site Reliability Workbook(구글) — SLO·에러 예산·온콜·포스트모템. 무신사에서 무너진 "재발 방지" 답이 여기 있다.
  • Designing Data-Intensive Applications(마틴 클레프만) — 분산 시스템의 근본. 고려사이버대 분산·병렬 컴퓨팅 수업과 겹친다.

같이 보는 블로그·문서

  • kubernetes.io 공식 문서 Concepts — 책에서 막히면 같은 주제의 공식 문서를 먼저 연다. 1차 출처다.
  • Learnk8s 블로그 — 그림으로 설명하는 네트워킹·스케줄링·오토스케일링. 6장 네트워크 장과 짝이다.
  • Karpenter 문서 — 무신사 준비 때 본 NodePool·consolidation. 9장 kubelet과 노드를 읽을 때 같이 본다.
  • 카카오페이 기술 블로그, 우아한형제들 기술 블로그 — 국내 회사가 쿠버네티스를 실제로 어떻게 굴리는지. 면접 상대의 언어다.
  • Container Solutions 블로그, CNCF 블로그 — 새 도구가 나오면 먼저 나오는 곳.
  • Kubernetes The Hard Way — 11~12장(컨트롤 플레인·etcd)을 읽은 뒤 주말 하루에 한 번 따라 한다. 책의 내용이 손에 붙는다.
