출처는 다음과 같다.

- `16-case-xpand.md`의 사례 원고 S3~S11 (4샤드의 한계, 대안 판정, TiDB 기각, 전환 실행, 50% 절감, 점검 체계 편입)
- `12-cloudops-original-deck.md` 7쪽 (TiDB POC), 11쪽 (DB 점검 17항목)
- MariaDB 보도자료 2022-09-23 (원장 44행의 링크)

| 항목 | 채울 내용 |
|---|---|
| 1. 언제, 어디서 일어난 일인가 | 2020년 3월부터 2021년 10월까지 한 일이다. 당시 DB 약 1,000대를 운영하고 있었다. |
| 2. 무엇이 걸려 있었나 | 리샤딩과 유지보수 때 순간 중단이 있었고, 앱에서 수동으로 샤딩했으며, 확장에 상한이 있었다. |
| 3. 내가 무엇을 결정했나 | 요구 조건(무중단 수평 확장, 단일 DB로 인식, 운영 부담 축소)을 정한 일과, 같은 검토 절차로 TiDB를 기각한 일을 쓴다. |
| 4. 내 손으로 한 일은 무엇인가 | PoC를 내가 했는지, 전환 계획을 내가 썼는지, 컷오버 때 내가 어디에 있었는지 쓴다. |
| 5. 숫자는 무엇인가 | DB 비용 50% 감소(벤더 공개 사례), 노드 50대 이상, 일 수백억 건 요청(벤더 사례 표기)을 쓴다. |
| 6. 결과는 무엇인가 | 단일 시점 일관 백업을 확보했고, 고사양 VM 의존을 없앴으며, 점검 체계에 편입했다는 것을 쓴다. |
| 7. 다시 한다면 무엇을 바꾸겠나 | TiDB를 기각한 근거를 지금 다시 보면 어떤지 쓴다. |
